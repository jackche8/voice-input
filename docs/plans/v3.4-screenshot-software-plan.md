## 四、目的

一个可安装的独立软件：双击（或开机）启动后由软件自己拉起并看护后台服务，界面在独立窗口里，首次启动在设置页一键装齐模型与运行环境；新增截屏标注；Linux 出 .deb 安装包，Windows/macOS 打包脚本就绪。

## 五、逻辑流（现状 → 目标，★ 为变化）

### 5.1 启动与看护

```
现状(Linux)：桌面图标 → start.sh → 门闩判定 → systemd 启 4 个单元（各自重启/看门狗）→ 打开浏览器
现状(Win/Mac)：脚本 → 依次后台拉起 4 进程（无看护）→ 打开浏览器
目标(三系统同一套)：★应用入口（单例）→ ★看护层：按序拉起 Ollama → ASR（已安装才拉）→ Web 服务，
      按 /api/version、/health(loaded)、端口判就绪；崩溃退避重启；应用退出时停掉全部子进程；日志写用户数据目录
      → 热键/底栏/截屏（现守护进程能力，在应用主进程内）→ 托盘常驻 → ★主窗口（系统网页内核）载入工作台
```
- 应用主进程 = 现桌面守护进程的升级：它已是常驻 Qt 进程（托盘、热键、底栏、截屏），再承担看护层与打开主窗口。
- 主窗口是单独的窗口进程（系统网页内核需要自己的界面事件循环，不与 Qt 混在一个进程）；关窗口只关这个进程，应用继续常驻托盘；托盘「打开主界面」再开。
- 「已安装即运行」：看护层每一轮自己检查各组件是否已安装（以文件为唯一事实：Ollama 程序存在、识别运行环境清单存在、识别权重完整），装好的组件就拉起并保持运行；不设「组件已安装」事件。设置页不再有「启动」按钮（删除 systemctl 启动任务）。
- 开机自启：用平台适配层已有的 `configure_autostart`（目前无生产调用方），默认开启，设置里可关。

### 5.2 数据与程序分离

```
现状：代码目录 = 数据目录（项目根 .config.json、.cache/…、certs/、.web_input_token）
目标：★程序目录只读（安装位置）+ ★用户数据目录（Linux XDG_DATA_HOME/XDG_CONFIG_HOME，Windows %APPDATA%，macOS ~/Library/Application Support）
```
- 路径只有一处权威定义（现 `ProductionPaths` 拆成「程序根」与「数据根」），全部写死的项目根路径改为从它取；启动命令不依赖当前目录。
- 从源码运行与安装版用同一套规则（开发时数据也在用户数据目录）。

### 5.3 首次启动安装（设置页）

```
现状：Ollama 程序（仅 Linux）→ 拉 4b 模型 → ASR 权重（前提：手工建好的 venv-asr）
目标：★「一键装齐」一个按钮 = 业务层顺序任务：装 Ollama 程序（按平台）→ 等看护层报告 Ollama 运行 → 拉 4b 模型 → 安装识别运行环境（按平台与显卡选：Linux+NVIDIA = vLLM + CUDA torch；其他 = Transformers + CPU/MPS torch；固定版本、校验来源）→ 下载 ASR 权重
      每步单独显示进度；某步失败即停在该步并显示原因，从该步重试；看护层按文件发现新装好的组件并拉起
```

### 5.4 截屏标注（新功能）

```
Ctrl+Alt+A（可改，沿用冲突检测）→ 复用红十字框选器 → 选区冻结 → 迷你工具条（模板 A：矩形·箭头·文字·马赛克 │ 撤销 │ 复制·保存 │ 取消）
  → 复制：PNG 写入系统剪贴板 → ★自动关闭 ；保存：PNG 存到「图片/Ollama Voice Input/」→ 显示路径 → ★自动关闭；Esc/取消 → 关闭
```
- 工具条位置规则与原位浮窗迷你菜单一致（框下 → 框上 → 框内）；点框外不关闭（防误丢标注）。
- 剪贴板写图片由平台适配层提供（Linux X11/XWayland 用 xclip 持有选区；Windows/macOS 各自实现）；失败如实显示「复制失败」。

### 5.5 安装包与门闩

```
Linux：★.deb：声明系统依赖（tesseract+语言包、xclip、xdotool、portaudio、python3 + venv/gi/dbus、WebKitGTK）；
       安装时用随包附带的依赖包离线建立应用 Python 环境；★udev uaccess 规则授予当前登录用户键盘读取与 uinput；
       安装应用菜单项与守护进程 app id 的 .desktop；卸载保留用户数据
Windows/macOS：★打包脚本（自带 Python 的独立程序 + 安装器/磁盘映像）写好，本次不出包、无真机验证
门闩：v3.4 真机验收补测手机局域网语音页与双模型同机并存 → 证据齐 → 关闭并★删除门闩机制
```
- 删除（被软件化取代）：`systemd/*.service`、`_v3/units.py`、`start.sh`、`restart.sh`、`install.sh`、`uninstall.sh`、`scripts/start.ps1`、`scripts/start_macos.sh`、旧 `ollama-voice-input.desktop`、`sd_notify` 看门狗、设置页 systemctl 启动任务与「daemon 单元」能力项、显存预检读单元 ExecStart 的方式（改读看护层配置）；门闩机制在 D9 验收后删除。

## 七、验收（汇总）

1. 三系统共用一套启动与看护逻辑；Linux 真机：启动、崩溃自愈（每个子进程各杀一次）、退出清理、单例（重复启动只唤起主窗口）。
2. 主窗口：独立窗口显示工作台、设置、历史；不再打开浏览器；关窗口不退出应用。
3. 首次安装：空的用户数据目录下，设置页依次装好 Ollama 程序、4b 模型、识别运行环境、识别权重，每项完成后对应服务自动运行；任一项失败可见原因并可重试。
4. 截屏标注：与 annotate-a.html 一致；复制/保存后自动关闭；失败如实显示。
5. .deb：本机安装、启动、卸载；设备权限无需加组与重新登录。
6. 门闩：手机局域网语音页与双模型并存补测通过后删除门闩机制，正常启动。
7. Windows/macOS：路径、看护、窗口、剪贴板图片等平台差异由自动化契约测试覆盖；打包脚本存在且语法检查通过；报告标明未经真机。
8. 闸门 `--layer all` 全绿。

## 八、执行约束（分身攻击后补充，2026-11-20，18 项全部采纳）

1. **本机切换**（阶段一，在门闩删除之后）：停止、禁用并删除 `~/.config/systemd/user/` 下 4 个单元与 drop-in，删除 install.sh 时代的 `/etc/udev/rules.d/99-uinput.rules`（input 组成员关系保留，可能被其它工具使用）；看护层启动时若端口被非本应用进程占用，明确报错不抢占。
2. **子进程不成孤儿**：子进程随父进程退出（Linux `PR_SET_PDEATHSIG` + 按进程组终止，ASR 自建会话需整组终止；Windows Job Object；macOS 父进程监测）；看护层把子进程 PID 记在用户数据目录，启动时清理上次残留。应用主进程崩溃不自动重启（已知限制，原 systemd 看门狗随之取消）。
3. **组件状态单一来源 = 看护层**：应用主进程把每个组件状态（未安装 / 启动中 / 运行 / 退避中 / 已停止并附原因）上报服务端；服务端只缓存最新一份（可由重连后重报重建），设置页只读它。删除设置页读 systemctl 的全部路径。
4. **安装任务不随服务端重启丢失**：安装 worker 在独立会话/进程组运行，进度与结果写用户数据目录，服务端只读；服务端重启后从文件恢复任务列表，可继续或清理后重试；安装前预检磁盘空间。
5. **门闩**：D9 补测（手机局域网语音页、双模型同机并存）不依赖新代码，**阶段一开始时**在现有 systemd + acceptance 环境上由用户完成；证据齐后删除门闩机制（含 `unmet_gates` 字段、设置页显示与全部读取方），**先于本机切换**落地。开发与测试期间的临时运行显式设置 `OVI_ACCEPTANCE_RUN=1`。
6. **日常使用不中断**：阶段一开始时（D9 补测之前），主控用 `git archive f311eca` 把 v3.3 导出为仓库外的固定副本（`~/.local/share/ollama-voice-input-v3.3-stable/`，静态文件，非分支、非 worktree；隔离理由：开发中的工作树代码不得被日常使用的 systemd 单元加载），先 `mkdir -p` 目标目录再解包；副本内的 `.venv`、`.config.json`、`.cache/`、`certs/`、`.web_input_token` 链接回仓库原文件（`.venv` 不在 git 中，单元的 ExecStart/ExecCondition 用 `@VENV@/bin/python3`，`_v3/units.py:116`），用副本自带的 `install.sh --update` 把 4 个单元改指向副本并重启；完成判据：`systemctl --user is-active` 4 个单元均为 active，且守护进程日志显示按下区间新路径；日常使用（含 D9 补测）都在副本上进行，与开发工作树彻底隔开。本机切换时删除副本与单元。切换后开机自启指向新的应用入口；验收含「重启机器后热键、语音、截屏翻译照常可用」。
7. **迁移清单**（主控手工、一次性）：迁移证书目录（含 `ca.pem`）、`.web_input_token`、`.config.json`、历史、jobs、ASR 权重、Ollama 程序与模型；`venv-asr` 不迁移，改由设置页新的「安装识别运行环境」任务重建（同时作为该任务的真机实测）。
8. **主窗口证书**：Linux 窗口进程直接用 gi 的 WebKit2GTK 4.1（本机已装），只信任本应用证书且仅限 127.0.0.1，不用全局忽略；Windows/macOS 窗口进程用 pywebview（WebView2/WKWebView），信任方式限回环地址，写入打包脚本说明（未经真机）。
9. **单例唤起**：持锁实例监听 Qt 本地套接字（`QLocalServer`，三系统通用）；第二个实例发送「打开主窗口」后退出。
10. **看护层不阻塞主线程**：看护层在独立线程运行，状态变化经 `QtUiBridge` 回主线程；测试：看护层等待就绪期间热键边沿 50ms 内处理、底栏动画不停。
11. **退避上限**：三个组件统一为连续失败 5 次（运行满 60s 计数清零；原 systemd 各单元取值不一，ASR 为 3 次/120s，此处统一取 5，不是沿用）即停止自动重启、标记失败与原因，设置页与底栏可见，提供「重试」；启动 ASR 前显存预检改读看护层配置。
12. **udev**：规则文件序号小于 73（如 `70-ollama-voice-input.rules`），键盘按 `ENV{ID_INPUT_KEYBOARD}=="1"` 匹配、`/dev/uinput` 加 `TAG+="uaccess"`，`modules-load.d` 开机加载 uinput；安全面与加入 input 组相同（当前登录用户进程可读键盘），写入说明。
13. **.deb 与 Python**：Depends 锁定系统 python3 小版本（本机 3.14）；postinst 建 venv 失败则安装失败、不留半装；postinst 预编译字节码；卸载删除程序目录内 venv，保留用户数据。
14. **截屏标注为 `CaptureFlow` 第三种模式**，与 Ctrl+Alt+X/O 共用框选器状态与 generation 互斥规则。
15. **新快捷键**：门户会话从 4 键变 5 键时 GNOME 弹授权；冲突检测覆盖 Ctrl+Alt+A。
16. **开机自启**：首次运行写入当前用户 `~/.config/autostart`（复用 `render_autostart_desktop`），设置里可关。
17. **源码运行与安装版共用用户数据目录**：单例互斥；配置结构变化导致旧版本读取失败记为已知限制（不加覆盖开关）。
18. **Transformers（无 NVIDIA）路径**：阶段一在本机用 CPU 实测一次安装与识别一句话的耗时，写入方案作为证据。

19. **组件失败可见**：Ollama/ASR 停止（退避用尽）时，看护层发一条现有 error 事件到底栏；失败的正是服务端时，由应用直接把托盘置为错误（事件通道不可用）。
20. **子进程会话整体清理**：任何子进程退出后先终止其整个会话再进入退避；PID 记录含会话号与组长启动时间，启动清理按会话查杀残留（显存不被残留进程占用）。
21. **全局 Esc 交给窗口**：浮窗句柄协议增加 Esc 处理，原位浮窗即关闭，标注窗口两段式（输入文字时只结束输入）。
22. **运行中升级**：.deb 的 prerm 通过单例套接字通知正在运行的应用退出，避免新旧代码混跑；升级后由用户（或开机自启）再启动。

补充验收：应用被 kill -9 后再启动无残留、无端口冲突；切换后重启机器自启可用；第二次启动只唤起主窗口；看护层等待期间热键与底栏不卡；安装中途服务端重启后可继续或重试；迁移后手机原地址免重扫、证书仍被信任；.deb 覆盖升级保留数据与快捷键授权；uaccess 装完免重新登录即生效（`getfacl /dev/uinput` 可见当前用户）；新快捷键门户获批且冲突检测有显示。

- 〔已由 10.14 取代 → 10.15.4 / N5：改用包装进程，不用 preexec_fn〕 Linux：`Popen(..., start_new_session=True, preexec_fn=_set_pdeathsig(SIGTERM))`（ctypes prctl(PR_SET_PDEATHSIG)）；终止 `os.killpg(pid, …)`。PDEATHSIG 绑定**创建子进程的线程**：只允许在看护线程内 spawn，且看护线程活到应用退出（F10）。ASR sidecar 自身 setsid 时已是组长（`process_guard.enter_new_session` 对此已容错），组内 vLLM 子孙随组终止。

### 10.11 映射发现（交主控裁决）

**F1【需裁决】「按序拉起…判就绪」是否串行阻塞。** 5.1 写「按序拉起 Ollama → ASR → Web 服务，按 /api/version、/health(loaded)、端口判就绪」。ASR 加载实测数十秒到数分钟（原单元 start 超时 300s，`production.py:291`），若等 ASR 就绪才拉 server，主窗口与设置页（含安装任务）要等这么久；原 systemd 也只是 After= 排序、不等就绪（`systemd/ollama-voice-server.service:4`）。推荐 A：按序**拉起**、各自独立判就绪，server 不等 ASR/Ollama 就绪（它本来就探测二者）；备选 B：严格串行。

**F2【需裁决】Windows 数据目录。** 5.2 写 `%APPDATA%`（漫游配置文件），模型与运行环境数 GB（ASR 权重 4.4G、cuda 运行环境约 7G）放漫游目录会被域环境同步。推荐 A：配置/令牌/证书 → `%APPDATA%`，数据 → `%LOCALAPPDATA%`（10.6-A 已按 A 写）；备选 B：全部 `%APPDATA%`。

**F3【需裁决】识别运行环境的 Python 版本与来源。** 现 venv-asr 是 uv 托管的 CPython 3.12.13（`.cache/v3-feasibility/venv-asr/pyvenv.cfg`：uv 0.11.3、3.12.13；vLLM 0.14.0、torch 2.9.1+cu128），而系统与应用 Python 是 3.14.4；5.3 只写「固定版本、校验来源」。推荐 A：安装任务下载固定版本 uv 官方发行包（sha256 校验）→ uv 安装固定 CPython 3.12.x（python-build-standalone）→ 按变体用带 hash 的锁文件安装（10.6-D）；Windows+NVIDIA 本次按 cpu 变体安装（vLLM 无 Windows 官方轮子）、记已知限制。备选 B：要求用户自备 Python 3.12。

**F4【需裁决】模板 annotate-a.html 与 D8 不一致。** 模板 :117 写复制「不关窗」、:118 保存失败用「抛错」；D8 定复制/保存后自动关闭。推荐：复制成功立即关、保存成功显示路径 2.5s 后关、失败都不关（10.6-G 已按此写）；保存结果用 `SaveResult` 返回值而非异常（回调边界不用异常做控制流，测试也更直接）。

**F5【需裁决】组件失败在底栏的可见性。** 八.11 要求失败「底栏可见」，而底栏唯一来源是服务端事件流（`_desktop/status.py` 经 server 回到 `event_stream`）；失败的组件若正是 server，本条消息无法经它到达。推荐 A：一般组件失败走 PlatformStatus.error（同一通道）；server 自身 stopped 时，应用直接把托盘置 error 并在托盘提示里写原因（唯一例外，写进 event_stream 说明）；备选 B：只在设置页可见（server 失败时设置页也打不开）。

#### 10.15.4 会话整体清理与 preexec 方案（B4、N5）
- 进程包装（取代 10.6-B 的 preexec_fn 与 orphan_guard 两处写法）：`_platform/child_guard.py`，所有 POSIX 子进程都以 `[sys.executable, -m, _platform.child_guard, --mode M, --parent <应用 PID>, --, *argv]` 启动，`Popen(start_new_session=True)`：
  - Linux `--mode pdeathsig`：`prctl(PR_SET_PDEATHSIG, SIGTERM)` → 若 `os.getppid() != --parent`（父进程已先退出）立即退出 1 → `os.execvpe(argv…)`。PDEATHSIG 跨 execve 保留（非 set-uid 程序），PID 不变。
  - macOS `--mode watch`：以 argv 启动孙进程（同会话），每 0.5s 查 `os.getppid()`，父进程不在 → killpg 整组后退出；孙进程退出 → 以其退出码退出。
  - **理由**：`preexec_fn` 在 fork 与 exec 之间运行 Python 代码，父进程是多线程的（Qt、看护、发送、读事件流线程），Python 文档明确此用法可能死锁；包装进程把 prctl 放到一个单线程的新进程里执行，fork 与 exec 之间不跑 Python 代码（`start_new_session` 在 C 层完成）。代价是每次拉起多一次 Python 启动（约 30–50ms），拉起频率极低，可接受。
- 子进程退出处理：看护线程 poll 到任一组件进程退出 → **先** `handle.terminate_session(stop_timeout)`（终止该组件整个会话里仍存活的进程：Linux 按 /proc 中 `session == sid` 枚举；macOS 按进程组；Windows `TerminateJobObject`）→ 再记失败、进入退避。超时 kill 与 `stop_all` 同样走 terminate_session。
- PID 记录（取代 10.6-B 原格式）：`run/children.json = {"app_pid", "app_identity", "children": {name: {"pid", "sid", "leader_starttime"}}}`（Linux sid = 组长 PID，leader_starttime = /proc starttime；macOS sid 记进程组号、starttime 记 `ps -o lstart=`；Windows 只记 pid + 创建时间）。
- 启动清理：对每条记录——组长仍在且启动时间与记录不同 → PID 已复用，跳过；否则（组长在且一致，或组长已不在）→ 终止 `session == sid` 的全部进程（TERM → 5s → KILL），确保显存不被残留 vLLM 进程占用。依据：Linux 在会话仍有成员时不会把该会话号分配给新进程（会话号即组长 PID，被成员引用）。
- 契约方法（`_platform/child_process.py`）：`ChildHandle.terminate_session(timeout_s)`；`kill_recorded_session(record) -> list[int]`（返回被终止的 PID）。
