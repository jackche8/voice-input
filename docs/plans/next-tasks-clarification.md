## 二、本地翻译优化（新需求，需澄清后出方案）

**用户原话**：输入结束延迟 1S 自动翻译；翻译自动识别支持互换，比如设置了中英翻译模式，最好能识别中英或者手动切换。

**现状（事实）**：配置只有单一目标语言 `translate_target_lang`（默认 `zh`，`_contracts.py:617`）；工作台文本翻译需手动触发（待核实触发方式）；截屏翻译也只用这一个目标语言。

**拟定做法**：
1. **语言对模式**：配置由「目标语言」改为「语言对」（如 `zh⇄en`），方向由后端按输入自动判定——中文为主 → 译英文，英文为主 → 译中文。判定放在逻辑层一处实现（按文字脚本占比判定，确定性、无模型调用），前端只显示判定结果，不自行重算（一条规则一处实现）。
2. **手动互换**：工作台加「⇄」按钮，临时固定方向（覆盖自动判定），再次点击或清空输入恢复自动。
3. **输入停止 1 秒自动翻译**：前端业务层防抖（最后一次输入后 1000ms 发起）；新输入到来时作废在途请求结果（沿用现有单调请求序号机制），只显示最新一次的译文；空输入不请求。
4. 删除 `translate_target_lang` 及其全部读取方，迁移到新配置字段（不并存两套）。

**待用户澄清**：
- Q1 自动识别与互换只用于工作台的文本翻译，还是截屏翻译（Ctrl+Alt+X）也按语言对自动判方向？（推荐：两处同一规则，截屏翻译也自动判定）
- Q2 支持哪些语言对？只做中⇄英，还是允许选其他语言对（如中⇄日）？（推荐：先只做中⇄英，结构上支持扩展）
- Q3 中英混合输入（如中文句子里夹英文术语）按什么判定？（推荐：按文字占比多者为源语言）
- Q4 1 秒自动翻译是否需要开关？（推荐：默认开启，设置里可关）

**验收草案**：输入中文停 1 秒自动出英文；输入英文停 1 秒自动出中文；连续输入只发最后一次请求；点「⇄」方向立即反转并重译；截屏翻译按 Q1 结论生效；闸门全绿（含真实 4b 用例）。

## 三、暗色主题下拉框看不到选中内容（缺陷）

**现象**：暗色主题下，下拉框的选中内容 / 展开列表看不清。

**已核实**：`static/v3/css/studio.css:240-248` 只给 `.box-head select` 本体设了暗色背景与文字色；`static/v3/css/theme.css:236` 的 `select.field` 未设选项颜色；全部 CSS 中没有 `color-scheme` 声明。展开的选项列表由系统/网页内核原生绘制，暗色主题下沿用浅色配色，导致浅字配白底。

**拟定做法（根治）**：在主题根上按主题声明 `color-scheme: light` / `dark`，让原生控件与下拉列表跟随主题；`select` 与 `option` 的背景、文字色统一取主题变量（`--c-surface`、`--c-text`），一处定义、所有下拉框复用；在独立主窗口（WebKitGTK）与浏览器中都验证。

**待用户澄清**：Q5 出问题的是哪个页面的哪个下拉框（工作台语言选择 / 设置页 / 全部）？截一张图最快。

**验收**：暗色、亮色两种主题下，所有下拉框收起时的选中值与展开列表都清晰可读；在主窗口与浏览器中各核对一次；UI 测试补一条静态检查（主题声明 `color-scheme`、下拉样式取主题变量）。

## 四、框选起点跳动（缺陷，影响截屏翻译 / OCR / 将来的截屏标注）

**现象（用户）**：截屏框选时鼠标起始位置有问题，总是从中点起始，再跳到鼠标当前位置。

**根因（已核实代码，待真机复现确认）**：
- 触发：按 Ctrl+Alt+X / Ctrl+Alt+O 打开全屏框选器。
- 路径：`_ui_desktop/region_selector.py:82-88` `_initial_cursor_pos` 用 `QCursor.pos()` 取初始光标；我们的界面在 GNOME Wayland 下经 XWayland 运行，X 客户端在指针进入自己的窗口之前拿不到真实指针位置（读到的是旧值或无效值），不在屏幕范围内时代码退回到**屏幕中点**。
- 结果：十字线先画在中点（或旧位置），第一次移动鼠标后才跳到真实位置——即用户看到的「从中点跳到鼠标位置」。
- 性质：退回中点是猜测值（兜底），不是真实位置。

**拟定做法（根治）**：删除「猜初始位置」的逻辑——在收到第一个真实指针事件（进入窗口或移动）之前不画十字线与坐标读数，只显示「移动鼠标开始框选」提示；按下的起点一律取按下事件自身的位置（现已如此，需用例守住）。不加延时或轮询。

**待用户澄清**：Q6 跳动发生在「框选器刚出现时十字线的位置」，还是「按下鼠标开始拖拽时选框的起点」？（若是后者，需要另查按下事件与 XWayland 指针同步问题。）

**验收**：框选器出现时不在错误位置画十字线；鼠标一动十字线就在真实位置；按下即从光标处开始拉框；截屏翻译、OCR（与阶段二标注）三条路径一致；ui_desktop 补用例（无指针事件时不画十字线、按下起点等于按下位置）。
